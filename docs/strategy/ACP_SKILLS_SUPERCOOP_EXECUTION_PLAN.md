# ACP Skills Supercooperation Execution Plan

Status: active strategic upgrade plan  
Owner: ACP senior researcher / engineer  
Audience: maintainers, paper authors, evaluators, workshop reviewers

## Executive thesis

ACP should treat the skills layer not as a prompt library or convenience wrapper, but as a **constitutional procedural layer for public reasoning under bounded attention**.

The protocol defines canonical deliberation objects and compatibility boundaries. The reference implementation executes those semantics. The skills layer should become the reusable, inspectable, portable surface where civic workflow safeguards live:

- routing discipline
- explanation faithfulness
- omission detection
- fairness and contestability review
- abstention and escalation
- protocol / adopter review

That is the strongest version of the project for the Foresight Supercooperation community.

## Why this basin is strongest

This framing aligns with the workshop's center of gravity:

- AI for democracy without AI sovereignty claims
- cooperation across difference under overload
- anti-concentration through inspectable and portable procedures
- human-steerable governance rather than model mystique
- bounded shared reasoning rather than consensus theater

## Strategic attractors

### A1. Collective deliberation is a procedural skill problem
The strongest memetic framing is that better civic reasoning does not come only from stronger models; it comes from reusable procedures that preserve disagreement, uncertainty, and escalation discipline.

### A2. Skills as constitutional workflow modules
The skills layer should encode bounded norms for what the system is allowed to do, what it must refuse, and when it must escalate.

### A3. Bounded attention is the root problem; skills are the control surface
ACP remains the protocol for attention coordination. Skills become the inspectable control surface for how that coordination is carried out.

### A4. Pluralism-preserving compression
The skills layer should explicitly defend against false consensus, minority erasure, tokenistic bridge exposure, and unsafe explanatory compression.

### A5. Interoperable civic procedure sharing
Institutions should be able to share routing, omission, fairness, and escalation procedures without sharing one UI or one model stack.

## Strategic hypotheses

### H1. Skills primarily improve failure-mode control, not generic task quality
Primary gains should be measured in false-consensus reduction, omission catch, contestability preservation, escalation correctness, and claim-boundary obedience.

### H2. Skills are a more portable control surface than monolithic prompting
The same procedural modules should transfer more reliably across providers and runtimes than ad hoc freeform prompting.

### H3. Compositions matter on hard civic tasks
Single skills are useful, but the most valuable behavior emerges from defense-in-depth compositions on overloaded, institutionally sensitive tasks.

### H4. Human review benefits from explicit skill traces and artifacts
Skills should make runs easier to inspect, contest, and repair, not only easier to generate.

## Desired end state

The ideal ACP skills layer has:

1. a small canonical constitutional core
2. stronger machine-readable framing
3. richer human-readable skill documents
4. cross-domain civic compositions beyond one flagship denominator
5. inspectable skill maps and lineage surfaces
6. structural gates that enforce the stronger standard
7. paper/repo framing that introduces the skills layer early and seriously

## Canonical constitutional core

The constitutional core should be treated as the load-bearing public reasoning stack:

1. `epistemic-routing`
2. `digest-and-explanation`
3. `omission-critic`
4. `fairness-contestability-critic`
5. `abstention-escalation`
6. `protocol-implementer-review`
7. `public-hearing-triage` as the frozen flagship domain denominator

## Workstreams

### W1. Constitutional framing and public entrypoints
Goal: make the layer legible as procedural governance rather than prompt inventory.

Deliverables:
- stronger `skills/README.md`
- dedicated constitutional skills doc
- explicit claims / non-claims and reviewer entrypoints that foreground skills earlier

### W2. Machine-readable constitutional core
Goal: make the core stack inspectable by tooling, not only prose.

Deliverables:
- registry-level `constitutionalCore` metadata
- SDK helper for constitutional skill discovery
- generated constitutional skill map artifact

### W3. Core skill specification upgrade
Goal: make each core skill look like a serious governance module.

Required sections for every constitutional core skill:
- Constitutional purpose
- Failure modes targeted
- Required evidence for valid use
- Produced artifacts
- Allowed claims
- Forbidden claims
- Human override points

### W4. Cross-domain civic compositions
Goal: show the layer transfers beyond the single flagship denominator.

Deliverables:
- `public-hearing-end-to-end` retained as flagship
- new participatory-budget composition
- new school-board composition

### W5. Structural gate hardening
Goal: ensure the stronger framing is enforced, not only suggested.

Deliverables:
- audit checks for constitutional-core sections
- tests for discovery helpers and constitutional map generation

### W6. Paper-facing reframing
Goal: make the selected title `Collective Deliberation Is a Skill Issue` more defensible.

Deliverables:
- abstract / introduction framing note
- earlier foregrounding of skills as constitutional procedures
- clear distinction between protocol truth and procedural skill truth

## Immediate execution packet

This packet should implement the repo-visible, high-leverage pieces now:

1. Add a machine-readable constitutional core to `skills/registry.json`
2. Add a human-readable constitutional skills map
3. Upgrade the seven constitutional-core `SKILL.md` files with stronger governance sections
4. Add at least two cross-domain civic compositions
5. Harden `skills:audit` to check the new constitutional-core sections
6. Add SDK helpers and tests

## Success criteria for this packet

A reviewer should be able to answer all of these within minutes:

- What are ACP's constitutional skills?
- Which failure modes do they target?
- Which claims are allowed vs forbidden?
- Where does human override enter?
- How do the skills compose across multiple civic domains?
- How can the layer be reproduced and inspected?

## Non-goals for this packet

This packet does not itself complete:

- human-review evidence collection
- broader live-provider wave expansion
- full manuscript rewrite
- operator-utility proof
- field-efficacy proof

Those remain next-layer research work.

## Strategic title implication

If this packet succeeds, the skills-first framing becomes materially more defensible. The selected working title is:

- `Collective Deliberation Is a Skill Issue`

Backup directions remain:

- `Public Reasoning Is a Skill Issue`
- `Public Reasoning Is an Attention Problem`

The key point is that the chosen title is supported by repo structure, not only rhetorical taste.
