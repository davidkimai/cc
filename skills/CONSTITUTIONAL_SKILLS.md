# Constitutional Skills for Public Reasoning

ACP's skills layer should be read as a **constitutional procedural layer** over the protocol, not as a loose collection of prompts.

The protocol defines canonical objects and compatibility boundaries. The skills layer defines the reusable, inspectable procedures that help agents and operators use those objects without collapsing disagreement, hiding uncertainty, or overstating what the evidence supports.

The strongest architecture is not to turn skills into the protocol itself. It is to keep protocol truth stable while exposing procedure references, contest points, artifact expectations, adherence markers, and escalation provenance as first-class protocol-adjacent metadata.

## Core thesis

Collective deliberation under overload is not only a model problem. It is a **procedural skill problem**.

ACP Skills exist to encode and expose those procedures in a form that is:

- inspectable
- portable
- contestable
- composable
- bounded in its claims

## Constitutional core

These seven skills are the load-bearing constitutional core for the current ACP repo.

### 1. `epistemic-routing`
Purpose: coordinate participant attention without laundering disagreement into consensus.

Targets:
- false consensus
- unbounded bridge exposure
- dominant-view overexposure
- unsafe release of low-confidence routes

### 2. `digest-and-explanation`
Purpose: compress routed material into participant-facing outputs without hiding uncertainty or evidence limits.

Targets:
- explanation overclaiming
- untraceable digests
- false neutrality
- release-ready language unsupported by source material

### 3. `omission-critic`
Purpose: protect material issue coverage and minority-salience against compression loss.

Targets:
- issue omission
- stakeholder omission
- loud redundancy displacing useful dissent
- completeness overclaims

### 4. `fairness-contestability-critic`
Purpose: surface minority-erasure, tokenistic bridge exposure, and contestability gaps before release.

Targets:
- minority erasure
- tokenistic bridge exposure
- false neutrality
- contestability gaps

### 5. `abstention-escalation`
Purpose: preserve safe refusal and human-steerable escalation when evidence, confidence, or authority is insufficient.

Targets:
- unsafe automation
- low-confidence release
- critic override pressure
- authority mismatch

### 6. `protocol-implementer-review`
Purpose: keep interoperability honest by separating protocol compatibility from local adapter convenience names or README overclaims.

Targets:
- protocol drift
- compatibility overclaiming
- competing naming layers
- missing conformance evidence

### 7. `public-hearing-triage`
Purpose: provide the frozen flagship civic denominator where the full stack can be exercised against public-input overload.

Targets:
- hearing overload
- minority-signal burial
- benchmark overclaiming
- missing scale-boundary discipline

## Primary outcome family

ACP Skills should primarily be judged by **failure-mode control**, not only generic task quality.

Most important outcomes:

- false-consensus reduction
- omission detection
- fairness and contestability preservation
- escalation correctness
- claim-boundary obedience
- artifact trace legibility

## Human override principle

Every constitutional skill should make it obvious:

- what evidence is required
- what artifacts it produces
- what claims are forbidden
- when a human can or must intervene

Skills are strongest when they make human review easier, not when they hide it.

## Core compositions

The skills layer becomes more compelling when the same constitutional stack transfers across multiple civic workflows.

Current flagship compositions:

- `public-hearing-end-to-end`
- `participatory-budget-end-to-end`
- `school-board-tradeoff-review`

These compositions demonstrate that the same procedural safeguards can travel across domains without pretending that one model or one UI owns the workflow.

## Non-claims

The constitutional skills layer does **not** by itself prove:

- field efficacy
- fairness solved
- institutional legitimacy by default
- operator utility without human review
- broad superiority across all tasks and settings

Those boundaries are part of the design, not a weakness to hide.
